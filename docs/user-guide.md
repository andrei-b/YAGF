# YAGF user guide

See the [README](../README.md) for installation, builds and screenshots.

## Current workflow

The **Recognize** split button runs recognition on the current page or selected blocks. Its arrow menu contains **Recognize all** and **Math only**; single-page and whole-document actions have different icons. **Cancel** appears only during recognition. **Languages** opens the OCR language selector. With local Tesseract, choose **Add language…** to search for a language by name.

Zoom, **Fit page**, rotation, **Correct skew**, **Smart split**, and **Clear all blocks** are on the translucent toolbar at the top of the image preview. Its leftmost pin button switches between staying visible and appearing when the pointer approaches the top edge; this setting is remembered. The toolbar stays at the top of the visible preview when scrolling. Selecting a block replaces rotation and skew correction with block recognition, options, and removal controls. **Correct skew** detects the remaining text-line tilt and updates the saved angle, preserving other preprocessing settings. It moves the saved text, corrections, and regions through the recorded source coordinates. When skew correction is the latest undoable action on the current page, an **Undo skew correction** button appears beside it and restores the previous image, text, and blocks. The button follows Undo/Redo history and hides after undoing the correction or making another edit. **Clear all blocks** is also available in block context menus and supports Undo. Opening a project shows a loading indicator while its pages are restored and the first preview is rendered.

Open an image or PDF. The left navigation strip shows page miniatures and crop miniatures for saved image regions. The center is a zoomable page preview, and the right pane is a rich text editor with recognized words below it. Drag on the image to add OCR blocks. Click a block or its miniature to select it; drag inside to move it, drag an edge to resize it, or press Delete (or **Delete region**) to remove it. Creating, moving or resizing a block stops at neighboring blocks. The preview shows the allowed borders while you drag, and releasing the mouse keeps those borders. Hold the middle mouse button and drag to pan. Shift-click blocks on the page or Ctrl-click their miniatures to select several. **Recognize** processes the selected text blocks. Click empty space on the page or press Escape in the preview to clear the selection and recognize the whole page. **Recognize region** processes only the active text block. Blocks are saved in projects and all block changes support Undo/Redo.

Right-click a block on the page or its miniature for **Recognize block**, **Select block language**, **Copy block as image**, and **Remove block**. Copying uses the displayed, preprocessed page at its original pixel resolution, including rotation and skew correction. Zoom and selection outlines do not affect the copied image. With one block selected, the page's image context menu also offers **Copy selected block as image**. **Recognize block** uses that block's language and is disabled for non-text blocks. Each block can inherit the page language, use a specific OCR language, or be marked **Not a text**. Non-text blocks have a dashed outline, are skipped during recognition, and contribute no existing text from that area. A specific block language is passed to the selected OCR provider; fixed-language remote services must support that code. PaddleOCR-VL receives it as a language hint. Language and non-text choices are saved with the block.

After recognition, Ctrl-click a word box, or select consecutive words in the word list. Edit the text and use **Apply correction**. You can join words (`mod ernization` → `modernization`), split words (`ofthe` → `of the`), insert words, and delete words. Each corrected word keeps its contributing source rectangles; a merge across lines retains separate fragments, a split divides source geometry, and inserted words get an estimated box. **Bold** and **Italic** remain available. **Edit → Undo/Redo** also reverses text, layout, preprocessing, and OCR page changes; the undo history resets when opening a different source or project.

Drag the horizontal dividers between page and block thumbnails, and between recognized text and the word list, to adjust their heights. The dividers have a visible grip and highlight on hover; both panels retain a usable minimum size. The recognized-text pane starts with extra space, and the main workspace dividers also let you adjust panel widths. **Spell check** underlines unknown words in red as you edit. Right-click an underlined word, or open the keyboard context menu with the caret in it, to choose a replacement from the active dictionaries. Use **Apply correction** to save the edit to the project. **Automatic (block language)** follows a block's language, the page OCR language, or the desktop language for automatic OCR. Use the spelling-language selector to choose an installed dictionary explicitly. Combined OCR languages such as `eng+deu` accept words from either dictionary. Checking is local and uses the optional Enchant 2 runtime with system dictionaries (for example, `libenchant-2-2`, `hunspell-en-us` and `hunspell-de-de` on Ubuntu). If a requested dictionary is missing, the selector's tooltip explains it and underlining is suspended for that language selection. Spell-check underlines do not change OCR text, rich-text formatting, exports or Undo/Redo history. Recognition actions and block removal have icons in the toolbar and block menu.

Enable **Tools → Recognition → Preserve formatting** before recognition to estimate a matching installed font family, bold/regular weight, italic, and approximate size from the scan. This local image comparison works after any OCR backend, including PaddleOCR, and is saved with the project. It currently targets printed Latin text and common serif, sans-serif, and monospace fonts; an unavailable original font is approximated. Word-based OCR can retain different styles within a line. Backends returning whole paragraphs receive one dominant style per block, sampled from its first printed line; mixed formatting within those blocks and handwriting are not reconstructed. Use the editor's font selector and **Bold**/**Italic** to correct estimates, then apply the correction. Font styles persist through editing, projects, layout HTML, scientific HTML, and the searchable PDF text layer; searchable-scan PDFs retain the original scanned page appearance. Disabling the mode affects subsequent recognition and does not remove saved formatting.

Recognition uses one dominant font size for prose within each block, including all its lines and paragraphs. Drawn and AI-detected blocks take precedence over the OCR provider's subdivisions; a selected crop is treated as one block. This also applies with **Preserve formatting** off and in **Use raw OCR output** mode. Punctuation and short glyphs inherit the block size. Separate blocks can have different sizes, while formulas, bold/italic styling, and explicit font-size edits are preserved. Re-recognize a block to apply this rule to an older project. The common point size and image-pixel size are saved with the text and used in the editor and exports.

**File → Export → PDF → Export formatted PDF…** recreates corrected text visibly in the original page blocks, retaining margins, columns, and paragraph breaks. It uses saved font families and weights, estimates missing font information from the scan, and fits text within each source block. Words keep the recognized block font size vertically; horizontal fitting accommodates source word widths. For large OCR blocks containing multiple saved lines, a local Tesseract pass can recover line positions and align the saved wording to them; weak matches fall back to fitting the original block. Layout and font estimates made during export do not modify the project. The PDF retains source images, regions marked **Not a text**, tables, and unchanged decorative headings whose geometry cannot be matched confidently; their recognized text remains searchable behind those scanned regions. Pages without OCR retain their scanned appearance. Exact matching depends on the OCR geometry, available fonts, and the amount of corrected text that must fit. **Export searchable PDF…** continues to keep the complete scanned appearance with an invisible corrected text layer.

Use **Scan** on the toolbar or **File → Scan a page…** to discover SANE scanners, choose a device, resolution, and color mode, and import a page. The scanner list and selected device are remembered until YAGF exits, so reopening Scan does not repeat discovery. For AirScan network scanners, YAGF uses `airscan-discover` from the `sane-airscan` package to remember connection URLs; the backend's temporary device numbers can change between scans. **Refresh scanners** checks for changed devices. Scanning runs in the background and can be cancelled. You can also drop a local image or PDF onto the preview, or choose **File → Paste image from clipboard** (`Ctrl+Shift+V`) for a screenshot or image copied from another app. JPEG photo orientation metadata is applied consistently to preview, OCR, and PDF export. Scans and pasted images are saved under the app's data directory. The scanner action currently imports one page per scan.

Use **Improve page…** to inspect the original beside a processed preview. **Detect skew** estimates a correction angle using a locally binarized copy, so uneven paper lighting does not dominate detection. **Detect orientation + skew** also uses optional Tesseract `osd` data to correct sideways/upside-down text; the rotation selector works without OSD. **Adaptive binarization** applies local black-and-white thresholding to the actual OCR image. **Auto contrast** stretches faded scans, and **Denoise (grayscale)** removes isolated specks. The settings apply to the current page and to its OCR input, including region OCR. They are saved in the project and reapplied when it opens. Changing rotation, deskew, or line bend reprojects that page's OCR boxes, source fragments, corrections, and drawn regions. The text and review decisions stay intact, and Undo restores the previous image and geometry. Contrast, denoise, and binarization keep the existing boxes. The source image is never overwritten.

For a photographed page with a gutter shadow or bowed lines, open **Improve page…** and select the upright rotation. **Level shadows** estimates the paper brightness in small areas and corrects the grayscale image before thresholding. **Detect bend** compares rows of ink across the upper and lower halves of the page. When both halves support the same smooth bow, it sets **Line bend**. You can also adjust this value in the preview, including on a sparse page. A positive value describes lines dipping toward the middle. Then use **Analyze text and ink**, inspect the preview, and apply. The same saved geometry is used for OCR and scan export. The bend control models one smooth curve across a page; sharp folds and two-page spreads can need separate crops. Coordinate mappings are saved with the project: rotations and perspective mappings use projective transforms, while line straightening records a displacement mesh. PDF mappings use points in the rendered page’s top-left, downward-y frame; image mappings use decoded source-pixel edges. Native model coordinates retain their recognition-time frame. Old restored images without a recorded mapping are explicitly identified as restored-image coordinates; YAGF does not guess an original-image mapping or discard existing work if a requested transformation cannot be inverted.

For shaded or speckled scans, open **Improve page…**, select the upright rotation, then choose **Analyze text and ink**. A local Tesseract pass measures confident words in the selected OCR language (English when a remote engine is selected). If too few words are legible, YAGF retries on a smoothed, locally normalized, provisionally deskewed image. Agreement across text lines sets the fine skew. Word pixels calibrate the local black-and-white filter for the whole page, including unread text. The dialog reports how many words and lines supported the estimate. Inspect the preview, choose **Apply**, then recognize the page as usual. The project saves the estimated settings so reopening a page does not repeat the pilot.

Click **Recognize all** beside **Recognize** in the toolbar to OCR every page in the open document, including pages already recognized. This also works for a single image and processes the whole document regardless of selected blocks. For a PDF or DjVu document, pages run in sequence. The same command is available as **Tools → Recognition → Recognize all pages**. A progress dialog shows the number of pages recognized out of the total, and **Cancel** stops the queue. The dialog closes when recognition finishes or stops. Verified corrections are retained using source geometry and text alignment, including small OCR box shifts and token segmentation changes. Uncertain matches remain saved for explicit review in the verification queue; new OCR stays visible until a saved correction is restored. Source-linked deletions also survive reruns. Layout metadata still relies on compatible region IDs. To correct segmentation, select words on the preview and choose **Tools → Page & layout → Create region from selection**. **Tools → Page & layout → Edit layout…** lets you set each region's type and box and move regions up or down in reading order. The order controls plain-text and structured JSON export; layout HTML keeps words at their source coordinates. Region boxes are metadata and do not move individual word boxes.

**File → Recent projects** reopens the ten most recently opened or saved projects, including portable folders.

**Save project** writes a versioned `.yagf.json` file with corrections for all recognized pages; **Open project** restores the pages, boxes, edits, and word formatting. If the source is beside the project, its path is stored relative to the project. **Save portable project folder…** copies the source into an `assets/` folder and writes `project.yagf.json`; move that whole folder to another computer and use **Open portable project folder…**. The source copy is checked by SHA-256 when opened. The title shows `*` for unsaved work, and opening another document or closing the window prompts to save. The **File** menu exports plain text, structured JSON, layout HTML, a searchable PDF, or PDF/A. PDF export uses the source image with an invisible text layer made from the corrected words, so text extraction uses your edits. PDF/A conversion uses OCRmyPDF without rerunning OCR on that text layer. Pages are rendered on demand at their saved DPI (150 by default); all image-based exporters use the same resolution. PDF export runs in a worker thread with progress and cancellation. OCR and thumbnail generation run in subprocesses, and **Cancel** stops the current job.

The project and document JSON schemas are version 2. They record the source path, source and processed page dimensions, per-page quality and DPI settings, pending corrections and saved deletions, user-drawn image regions, engine ID and language, stable page/region/paragraph/line/word IDs, reading order, each word's source fragments and union box, original reading, current reading, source word IDs, confidence, review state, and basic formatting. Version 1 projects and earlier version 2 projects still load. Coordinates are pixels in the processed page image. Corrections survive confident text/geometry matches across reruns; uncertain matches remain pending for explicit review. OCR does not recover exact fonts or complete column layout; the editor keeps detected line and paragraph breaks and estimates relative text size. The searchable PDF text layer currently uses each word's union box. Flatpak packaging and broader distribution testing remain planned.

Projects also retain native recognition evidence: Markdown, structured model output, formulas, table metadata, figures, layout relationships, model versions, and input/crop provenance. Editing the document does not alter that evidence. Real word boxes remain exact; line/block output stays coarse. If a model returns no coordinates, YAGF uses an explicitly inferred editing block covering the submitted image or crop and records no model-produced box or source fragments. These optional fields do not prevent older projects from opening.

Recognition runs through `IOcrEngine` in `processing/`. Tesseract is the default provider. Choose **Tools → Recognition → OCR engine…** to use an optional remote service and enter its URL and bearer token if configured. The token stays in memory for this session; each provider's URL is saved in desktop settings. PaddleOCR and RapidOCR return line boxes, docTR and Kraken return word boxes, and Surya returns ordered layout blocks with region types. See [service/README.md](../service/README.md) for setup and the HTTP protocol. `DocumentProcessor` runs engine work asynchronously and handles PDF rendering, batching, and cancellation. The `core` document model has no Python or inference framework dependency.

### Add an OCR language

Open **Tools → Recognition settings… → Text recognition → Model**. Each installed local language appears by name, for example **Tesseract German (local)**. Choose one and click **Save** to use it for text recognition.

- **Add Tesseract language…** lets you search by name or code. Choose **Add to selection** for an installed pack, or **Install and add** for a pack available from your configured Debian or Ubuntu repositories. A system installation may ask for administrator authentication.
- **Remove Tesseract language from list…** hides a named entry when you click **Save**. Its pack stays installed and you can restore it with **Add Tesseract language…**. Hiding an entry preserves the language in use for OCR.
- To recognize multiple languages together, use **Add language…** beside the language field or in the toolbar's **Languages** menu. Adding French to English gives `eng+fra`, with English primary.

For a single block, right-click it and choose **Select block language → Add language…**. If you install a pack separately, click **Refresh** in the chooser. For remote OCR, the selected service determines which languages it supports.

**Named remote models** such as **Tesseract English** and **Tesseract Russian** come from the native OCR worker. To add **Tesseract German** to that same model list, first add a German profile on the worker. Then open **Tools → Recognition settings… → Refresh models**. Select **Tesseract German** under **Text recognition** and click **Save** when you want to use it. [Add a Tesseract profile on the worker](../service/NATIVE_TRAINING.md#add-a-tesseract-language-profile).

For a document with mixed languages, choose **Tools → Recognition → Choose OCR languages…** and check the installed Tesseract languages, or enter a combination such as `eng+deu` in the OCR field. The first language is primary. The selected combination is used for page, region, and batch recognition and saved with recognized pages. Tesseract's [language syntax and order behavior](https://github.com/tesseract-ocr/tessdoc/blob/main/Command-Line-Usage.md#using-multiple-languages) are documented upstream. PaddleOCR uses one configured model language per service; docTR, RapidOCR, Surya, and Kraken use `auto` in YAGF because their model vocabulary is selected by the service.

To review a doubtful word, select it in the image or word list and click **Review word…**. YAGF marks unreviewed words below 70% confidence in amber. The dialog shows the source letters at adjustable magnification in original, higher contrast, and black-and-white views. You can type a correction directly, or enter a vision model name and a complete OpenAI-compatible chat-completions endpoint, then click **Ask AI for readings**. A local [llama.cpp server with a vision model](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#post-v1chatcompletions-openai-compatible-chat-completions-api) is one option. Only that explicit click sends the cropped image and nearby text. The model's suggestions are never applied automatically: choose a candidate, inspect its letters, and click **Use correction**. The correction uses the existing undo stack. Endpoint and model are saved in desktop settings; the optional bearer token stays in memory. No AI model is bundled with YAGF.

### Navigating formulas and OCR problems

Click **Navigate** beside the page controls, or press **Ctrl+Shift+J**. The **Document navigator** searches the open document across pages. Click a result to open its page and select the word, formula, or block in the editor. **F4** and **Shift+F4** move forward and backward through the active results and wrap at the ends. You can also search by text or reason, or check **Current page only**.

- **Formulas** includes reviewed equations, individual inline expressions, and math blocks awaiting OCR. Select an expression and choose **Edit formula…** to edit its LaTeX.
- **Problem blocks** groups flagged words and saved corrections by block. It also finds text or math blocks with no reading on a recognized page and blocks that claim the same OCR word. Each result shows the reason.
- **Uncertain words** lists unverified words with low confidence, conflicting readings, spelling flags, or suspect geometry. Select a word to review or mark it verified.
- **Review queue** keeps the full list of outstanding issues, including unrecognized pages and saved corrections that can be restored or discarded.

### Reconstructing uncertain passages

Choose **Tools → Recognition → Document context…** to describe the document's subject, period, terminology or names; for example, “A German physics textbook about thermodynamics, published in 1920.” The description is saved with the project and supports Undo/Redo. Leave it empty to let the configured AI infer the subject from earlier recognized text, or combine both sources of context.

**Use earlier recognized text to infer subject and terminology** is enabled by default for each document. Word and passage review collect excerpts from up to three recent pages, including text before the selection on the current page, with the same OCR language setting. Excerpts include reviewed readings and unchanged OCR at 90% confidence or higher; omitted uncertain words are marked with `[…]`. The selected passage and later pages are excluded. Context is rebuilt for each review, so edits and Undo immediately affect the evidence. The description is limited to 4,000 characters and the excerpts to 6,000.

Select an uncertain word or passage, open **Review word…** or **Review passage…**, inspect the document context shown above the image, and click **Ask AI for readings**. This sends the description and excerpts together with the source crop and nearby text to your configured vision model. The model uses the subject to distinguish visually plausible readings and is instructed to return no candidates when the pixels are insufficient. Only **Use correction** changes the transcription. This adds context to the AI reconstruction step; page OCR continues to use the selected OCR engine. No separate summarization request is made.

Keep Tesseract as the page engine and open **Tools → Recognition → Specialist OCR…**. Enable **Formulas with Surya**, **Uncertain text with docTR**, or both. Enter the base URL of each running service and its bearer token if needed. This opts in for the current session. The services receive cropped line images during page, region and PDF batch recognition.

Tesseract provides the first reading and word positions. Lines containing common mathematical operators or lying in a layout region marked as an equation go to Surya. A line with any word below 70% confidence can go to docTR. Formula recognition takes priority when both routes qualify. If a service fails, YAGF reports the error and keeps the primary OCR. This pass relies on Tesseract locating text on the page. For an equation it misses entirely, use Surya directly on a drawn region.

Choose **Tools → Review → Review next specialist reading…** on the current page to compare a differing transcription with the original and the scan. **Copy specialist reading to editor** lets you use or edit it. **Ask AI for readings** uses the marked crop, nearby text and both transcriptions to propose a context-based reading. You can also select consecutive words and use **Review passage…** with a configured vision model independently of specialist OCR. Only **Use correction** changes the document. Pending alternatives survive saving and reopening the project. Accepted verbatim specialist readings record the contributing engine and support Undo.

### Inspect recognition history

Open **Tools → Review → Review OCR readings…**, then **Recognition history…**. Select an attempt to see its exact crop, engine/model/version/hash, original output, runtime and diagnostics, preprocessing fingerprints and coordinate frames, and accepted/rejected decisions. Unknown model details remain blank. These snapshots retain the frames used at recognition time even after you rotate or preprocess the page again.

**Use this reading** records acceptance. **Reject this reading** records rejection while retaining the current text. For specialist review, accepting the proposed reading records acceptance and choosing the original text records rejection. Save applies the review window's choices; Cancel discards those choices. Undo/Redo restores both text and decision history.

Successful, failed and cancelled recognition attempts remain in the project across OCR reruns. AI layout analysis retains the full unfiltered response, including analyses whose proposed blocks you did not apply. Exact crops increase project size; shared images are stored once per page.

### Pages containing text and formulas

Open **Tools → Recognition settings…**. The **Recognition** tab has independent **Text recognition** and **Formula recognition** model selectors, with model names, locations and availability. Choose a text language there as well. All discovered and saved models appear in the selector for their advertised capabilities; a formula-only model cannot be chosen for text. **Refresh models** updates availability while retaining your selections, including temporarily unavailable services. Changes take effect with **Save**.

Use **Page layout** for the layout service URL, minimum score and automatic detection. **Models & services** contains discovery hosts, custom service URLs, session tokens and optional companion text engines. Select a discovered layout model there and click **Use selected for layout**. Text, formula and layout choices persist across restarts. Discovery sends health/model-list requests only and checks OCR ports **8765–8769**, layout **8771**, the model gateway **8772** and direct PaddleOCR-VL **8082**. An explicit URL can use another port or a path prefix. The Jetson's installed **PP-FormulaNet_plus-L** is available for explicit formula selection; it does not replace the selected formula model automatically. See [OCR discovery](../service/OCR_DISCOVERY.md) for worker and tunnel setup.

Enable **Use AI page layout before Tesseract page and batch OCR** to refresh old automatic blocks with the selected AI layout service before recognition. Manual blocks are preserved. The layout result and formula crops are used in the same OCR job; selecting a layout URL alone does not enable this pass. Optional full-page companion OCR is separate from formula OCR. When both use the same service, formula requests finish first so a single-server inference slot cannot starve them.

With different text and formula engines, recognition runs both in parallel for formula blocks already identified by manual marking or AI layout. No additional option is needed. Formulas discovered from text OCR follow the text reading. Using the same engine or service URL for both roles keeps requests sequential. Cancellation stops both engines, and failed formulas keep their original text OCR.

In **AI page areas…**, the **Minimum model score** slider below the image filters the cached model results live, from 10% to 95%. The preview and block list update together without running the model again. Lowering the score brings back hidden proposals; your type edits and inclusion choices are preserved. The chosen score is remembered. **Analyze again** fetches a fresh result.

If a formula outline misses a limit, exponent or subscript, choose **Tools → Page & layout → Refine formula blocks**. In text and mixed blocks, YAGF looks for stacked fractions and equals signs within a line. Where clear gutters separate an expression from prose, it creates separate **Text**, **Math**, and **Text** blocks in reading order. It also starts at the ink inside each Math block on the displayed page and looks for nearby symbol groups, including inside adjacent text blocks. Distance, alignment and symbol size guide the search. When moving the shared boundary would cut through other ink, YAGF keeps that edge. Inspect the outlines, use **Undo** to reverse the refinement, or run **Recognize** to read the revised crops.

When a tall character or an integral limit extends into the next line, the shared outline can step around it. The neighboring block gets a matching notch, so each OCR engine sees only the ink assigned to its block. AI layout and block splitting use these outlines too. To apply them to blocks already on the page, use **Refine formula blocks**. If ownership is ambiguous, the command leaves the boundary in place.

When an inline integral has visible upper and lower limits, **AI page areas…** can give the expression its own **Math** block. Whole-page recognition also checks for detached limits in existing mixed blocks. Use **Recognize** to refresh a page whose integral was previously read without its limits.

AI page layout keeps overlapping blocks. In **AI page areas…** and **AI split selected block…**, each proposal can be included or excluded independently. When editing block edges directly on the page, you can drag an edge into a neighboring blank margin.

Overlapping text blocks can give OCR a complete view of a sloping line from either crop. YAGF compares word positions on the scan, including cases where one crop splits a word into several tokens. It favors reviewed text, then complete readings and OCR confidence. Words found by only one crop are kept, and repeated words on separate lines stay separate.

During page splitting and automatic block recognition, YAGF checks the tilt of confident OCR words across several lines against the scan. On a visibly tilted page without usable word boxes, it can run a local OCR preview. When the lines support a correction, YAGF deskews before locating blocks and maps existing corrections into the new coordinates. In AI layout review, **Apply areas** or **Apply split** saves the deskew and the reviewed blocks together. **Undo** restores their previous geometry.

To subdivide a large existing block, select it on the page or in **Image regions**, then choose **Tools → Page & layout → AI split selected block…** (also available in the Smart split dropdown and block context menu). YAGF sends only that block's crop to the configured AI layout service, giving the model a closer view. Inline formula detections can divide a paragraph horizontally between lines and vertically on the same line. In the preview, check the text before and after each expression and the numerator and denominator inside its Math outline. Review the proposed types and score filter, select at least two compatible subdivisions, then **Apply split**. Only the parent block is replaced; children inherit its language and their crop coordinates are translated back onto the page. Cancel, failed analysis or fewer than two selected subdivisions keeps the original block. Text and reviewed corrections are preserved, and the split can be undone. Model granularity still limits the proposals; for a boundary that cannot be refined safely, try splitting the larger block first or adjust its box manually.

YAGF keeps corrected block splits in the project when you save. Each example pairs the processed page image with the original proposal and the corrected boxes, content types, and stepped outlines. Further edits to the same split update its target. Undo and redo also restore the example. Subdividing a block from a previous split records the coarse block it corrected. Changing the proposed subdivisions in the preview also records that proposal and its reviewed result. An unchanged full-page detection produces no training example.

To collect examples from one or more saved projects, give the exporter a new output directory. The installed command is `yagf2-export-layout-training`. From a source checkout, run it with Python.

```sh
python3 tools/export_layout_training.py layout-dataset book.yagf.json another.yagf.json
```

The output contains lossless page PNGs under `images/` and one record per corrected split in `examples.jsonl`. Use `corrected` as the training target and `proposed` to study detector errors. All boxes and outline pieces use full-page pixel coordinates in `[x, y, width, height]` order. The `scope` field identifies the area of the split. An empty corrected list records removal of all blocks. An empty `content` field means the block inherits the page engine and has no explicit class.


Recognition settings show each model's advertised tasks, coordinate granularity, output formats, languages, image limit and batching support when available. Text and formula choices follow these capabilities, including for models from unfamiliar providers using the YAGF protocol. Refreshing discovery preserves your selected models. Older services remain usable with their legacy task defaults; unspecified capabilities stay unknown. Requests exceeding an advertised image limit or unsupported task/language fail before uploading the image.

The formula selection is saved independently of the text engine. It applies to page and batch recognition, selected Formula blocks, equations in Text + formulas blocks, suspicious-text formula retries, and **Math only**. PaddleOCR-VL receives the dedicated `Formula Recognition:` task and complete formula crops at the page's rendering resolution. The local Rapid LaTeX model remains the default. A failed or incomplete formula response keeps native OCR where available and reports a warning; cancellation discards the unfinished job. Optional service tokens stay in memory for the session. **Use raw OCR output** bypasses formula recognition.

For Russian prose with equations, set the local Tesseract language to `rus` (or `rus+eng` for bilingual prose), leave **Math only** unchecked, and click **Recognize**. On an unmarked page YAGF automatically finds and labels blocks, reads the prose, and sends the formula crops to the selected formula engine. The same detection runs during batch OCR. To inspect and adjust the proposed blocks before recognition, click **Smart split** under **Image regions**. Try the [Russian example project](../examples/math-review/russian-math.yagf.json). The preview marks **Text**, **Math**, and **Text + math** blocks. Right-click a block or its thumbnail and choose **Block content** to correct a label. You can resize blocks or draw your own. Running Smart split again refreshes automatic blocks and keeps manually edited ones.

Click **Recognize** with no selection for the whole page, or select specific blocks. You can edit the combined result in the recognized-text pane and click **Apply correction**. Keep the blank lines that separate OCR blocks. Text uses local Tesseract. Automatic recognition retains its paragraph, line and column order on both prose and mixed text/math pages, replacing only contiguous formula spans. Recovered words are inserted beside the nearest raw text line. The local math model processes just the formula crops together. Inline results appear as LaTeX between `\(` and `\)` in reading order. Smart split uses word boundaries, spacing, operators and fraction bars, so dense layouts and formulas that resemble ordinary words may need a manual label. Save the project to keep the blocks. The default local formula engine requires the math runtime described below; a remote formula engine uses its configured service instead.

During **Recognize**, YAGF looks for isolated italic *x*, *z*, *u* and *v*, Fraktur capitals, and large operators such as ∑, ∏ and ∫. On mixed pages it compares the printed glyph with math and ordinary letterforms from installed fonts. A strong match can supply the LaTeX for a single symbol, with the formula engine’s differing reading available for review. For a larger expression, YAGF looks above and below the operator for limits and to either side for nearby operands, then sends the combined crop to your formula engine. Full-page recognition can borrow nearby ink across a Math block boundary. **Recognize selected blocks** stays inside the selection. The editable outlines can still be adjusted with **Refine formula blocks**.

Automatic formula selection protects page ranges, footnote markers and prose, and skips incomplete glyph fragments and axis rules. A manually assigned **Math** block or a **Formula** block applied through **AI page areas…** overrides these protections, including when text OCR misreads formula symbols as Cyrillic words. During mixed-page recognition, an individual failed crop or a reading with unbalanced LaTeX groups keeps its native OCR without discarding successful equations elsewhere on the page. The verification queue marks new local math readings with **Check formula symbols**: balanced LaTeX can still contain incorrect operators, Greek letters or subscripts.

Compact assignments such as `рз=2` and `р3=2` are treated as possible mathematics even when their short variable names resemble Cyrillic words or identifiers excluded from spell checking. The same check handles separate OCR tokens such as `рз`, `=`, `2`. The formula model reads the original crop to recover Latin letters and subscripts; YAGF does not replace Cyrillic lookalikes by guessing from the text.

With spelling dictionaries and the local math runtime installed, recognition also checks unknown words as possible misread formulas, including Cyrillic text. This uses the page or block's OCR language and accepts a word found in any selected dictionary. Adjacent suspicious words on the same line are retried together; readings with mathematical structure appear as **specialist alternatives** in the **Review queue** in the document navigator and **Review specialist reading…**. The original text and source boxes remain until you accept an alternative. Names and unfamiliar technical terms are not automatically replaced. Recognized line-end hyphenations are checked as joined words in the verification queue and their fragments are excluded from formula retries. Explicit **Text** blocks and raw OCR mode skip these retries. Missing dictionaries disable dictionary-based detection for that language; on Ubuntu, Russian spelling uses `hunspell-ru` with Enchant 2. Retries are limited to 128 suspicious spans per page.

Recognition also retries unreviewed formulas as text with Tesseract. Confident readings supported by the page or block's spelling dictionaries appear as text alternatives, with hyphenated line endings checked as joined words. Accepting one restores ordinary text editing and export while retaining source geometry; keeping the formula leaves its math classification intact. Explicit **Math** blocks are respected. This check runs in mixed recognition and **Math only** mode, with up to 128 formula crops per page.

Right-click a page miniature or an empty area of the page preview and choose **Clear all blocks** to remove that page's block outlines and settings. Recognized text and the scan are kept. **Undo** restores the blocks.

Corrected layout is the default. Enable **Tools → Recognition → Use raw OCR output** to use Tesseract's raw text and reading order without automatic block-layout correction or formula recognition. This applies to page, block and batch recognition and is saved in the project. Turn it off to return to corrected layout.

### Local math OCR

Open [the two-equation example](../examples/math-review/equations.yagf.json) and click **Recognize**. The project enables **Math only** in the **Recognize** dropdown. Use this option for a page or selection made up entirely of equations. Each separated row of printed mathematics becomes an editable LaTeX block. For pages mixing prose and equations, leave **Math only** unchecked. With automatic local recognition, if the formula model is unavailable YAGF keeps the Tesseract reading and the detected block labels for review.

Recognition reports its current stage and formula counts in the status bar. Automatic formula passes have a 30-second budget and a five-second limit per crop; completed readings are retained and remaining candidates keep the native OCR text. Explicit **Math only** recognition permits longer passes. **Cancel** stops the active recognizer. Choose **Tools → Recognition → Use raw OCR output** for local Tesseract text without automatic formula checks.

Select an equation in the word list and click **Edit formula…** above the recognized text. Edit its LaTeX and watch the preview update. If several equations are selected, choose the one you want. **Save** applies the correction to its original position, including inline equations within prose. **Edit → Undo** reverses it. The live preview uses the optional `pdflatex` and `pdftoppm` programs. You can edit and save the source with either tool absent.

Enable **Use Unicode formulas** in the **Recognize** dropdown for Unicode output in the text editor and text, HTML, JSON, and searchable PDF exports. For example, `\(p_{3}=2\)` becomes `p₃=2`, and `\psi\leq1` becomes `ψ≤1`. The option applies to existing and future recognized formulas, is saved with the project, and supports Undo/Redo. The original formula-bearing LaTeX is retained for **Edit formula…**, LaTeX document export, and typeset PDF output. Switching the option off restores that source while preserving subsequent manual text edits.

Unicode output uses Greek letters, operators, supported superscript/subscript characters, linear fractions, and parenthesized roots. Scripts that cannot be expressed with the supported Unicode characters use `_(...)` or `^(...)`; matrix rows use newlines. Unsupported expressions retain their LaTeX and show a status notice. The converter uses the [Unicode superscript/subscript](https://www.unicode.org/charts/PDF/U2070.pdf) and [mathematical operator](https://www.unicode.org/charts/PDF/U2200.pdf) characters. **Use raw OCR output** bypasses automatic formula conversion during recognition.

**File → Export → Word document (.docx)…** creates an editable Word document in the reviewed reading order. It carries over headings, paragraphs, tables and figure crops, and starts each source page on a new Word page. Supported inline and display formulas become editable Word equations. This export uses Pandoc locally. On Ubuntu, install it with `sudo apt install pandoc`.

**File → Export current page…** exports the page shown in the editor. Choose Word, plain text, layout HTML, scientific book HTML, LaTeX or structured OCR JSON for recognized content. PDF, PNG and JPEG are also available before recognition. The PDF includes searchable text when the page has OCR. The suggested filename includes the source page number.

**File → Export → Text and HTML → Document as LaTeX…** exports recognized pages in their reviewed reading order, with headings, prose, inline/display math, tables, figure crops, and source page breaks. It uses retained LaTeX even when Unicode output is selected. Figure PNGs are placed in a generated `yagf-assets-…` directory beside the `.tex` file; keep that directory with the document. Exports run in the background, support cancellation, and preserve the previous destination if preparation fails. Prose is escaped and formula commands are validated before publication.

Compile with `pdflatex -no-shell-escape document.tex` for Latin/Cyrillic documents; the generated preamble also supports a complete LuaLaTeX installation for wider Unicode font support. Exporting the source itself does not require TeX. The preamble uses AMS math, graphicx, longtable, and multirow; the pdfLaTeX branch uses fontenc, inputenc, Babel, and cmap, while the LuaLaTeX branch uses fontspec and unicode-math.

Formula crops remove distant scan specks while retaining nearby punctuation. A crop with too many lines reports an error; turn off **Math only** for pages containing prose, or select a smaller equation region. Check Greek letters and subscripts against the scan, as the local model can confuse them.

**File → Export → PDF → Export formatted PDF…** keeps the scan for formula regions by default. To typeset display and inline equations from their current LaTeX readings, check **Typeset math formulas** in the save dialog. YAGF remembers your choice for the next formatted PDF export. Fractions, roots, scripts, and matrices use embedded fonts and vector rules. The surrounding prose stays selectable, and copying an equation follows the chosen LaTeX/Unicode output mode. If a reading contains an unsupported command, the export reports the page and location so you can correct it and export again.

YAGF can be built and used without TeX. When `pdflatex` is absent, the typesetting checkbox is disabled and formatted PDF export keeps the scanned formulas searchable. On Ubuntu, optional typesetting uses `texlive-latex-base` and `texlive-fonts-recommended`. For typesetting OCR blocks that combine Cyrillic prose and inline equations, add `texlive-lang-cyrillic` and `cm-super-minimal`. Compiling exported documents with tables also requires `texlive-latex-recommended` and `texlive-latex-extra`. LaTeX stays a host dependency for the AppImage; [packaging instructions](../packaging/README.md) include the complete install command.

The optional CPU engine uses RapidLaTeXOCR. Set up its local Python environment and download the weights once:

```sh
math_env="${XDG_DATA_HOME:-$HOME/.local/share}/yagf2/math-ocr/venv"
python3 -m venv "$math_env"
"$math_env/bin/python" -m pip install rapid-latex-ocr==0.0.9 requests 'numpy<2' 'opencv-python<4.12'
"$math_env/bin/python" -c 'from rapid_latex_ocr import LaTeXOCR; LaTeXOCR()'
```

## Scientific books

Choose **Tools → Recognition → OCR engine… → Surya**, open a scan, and recognize the page or use **Tools → Recognition → Recognize all pages** for a PDF. The Surya service detects layout, predicts reading order, and transcribes inline and display mathematics into LaTeX. Tables retain row and cell boundaries, header cells, and merged-cell spans. Figures and diagrams retain their source rectangles even when they contain no recognized text. See the [service setup](../service/README.md#surya).

Select one layout block to edit its transcription. In a table, tabs separate cells and newlines separate rows. In **Tools → Page & layout → Edit layout…**, compare the ordered regions with the page, correct a label or figure crop, and move regions up or down. Save the project to retain these edits.

**File → Export → Text and HTML → Scientific book as HTML…** writes a self-contained, reflowable document in the reviewed reading order. It includes selectable formulas in the chosen LaTeX/Unicode output mode, HTML tables and embedded PNG figure crops. A caption immediately above or below a single figure or table stays with it. Ambiguous and separated captions remain at their reading positions. Plain text and JSON exports follow the same formula output mode; JSON also retains original LaTeX when available. Check equations, table alignment and multi-column order against the scan before publication.

Run `ctest --test-dir build -V -R '^mathrecognition_tests$'` to check the eight typeset equations in [the math test sheet](../tests/data/math/equations.pdf). The test rasterizes each page at 300 DPI and compares local English Tesseract output with the reference. Verbose output shows the actual transcription for each known mismatch. Set `YAGF_STRICT_MATH_OCR=1` to make every mismatch fail. A separate check saves and reopens reviewed equations, verifies their text and HTML exports, checks the searchable text in both PDF modes, and removes raster images from the formatted PDF to verify that the equations still render at their source positions. These checks use Poppler and the local English model. The specialist response tests use fixtures. To measure a running Surya model on the same scans, set `YAGF_TEST_SURYA_URL` to its base URL and run `QT_QPA_PLATFORM=offscreen build/mathrecognition_tests liveSurya`. It compares LaTeX source after removing whitespace and outer math delimiters.

## Learn from corrections

For a large PDF, recognize and review a few early pages, then choose **Tools → Recognition → Recognize remaining pages**. This skips pages that already contain OCR, including pages with reviewed corrections. Stop and resume the batch when you want to review more pages.

Before each local Tesseract job, YAGF builds a case-sensitive vocabulary from earlier pages in the same document with the same OCR language setting. A reviewed source word qualifies immediately. An unreviewed reading qualifies after Tesseract or another word-box engine reports it at 95% confidence or higher on two separate pages. Correcting a reading removes its automatic support for later jobs. Up to 4,096 terms, prioritizing verified readings, are supplied through Tesseract’s temporary [user words file](https://github.com/tesseract-ocr/tesseract/blob/main/doc/tesseract.1.asc). Page and region OCR use the same hints as batch OCR. Tesseract still decides what the image says.

For an isolated symbol from a word-box engine, YAGF also saves a small shape sample with its OCR box. Select a symbol below 85% confidence to see whether its normalized shape exactly matches an earlier example. A visual suggestion requires either a reviewed reading or readings at 95% confidence on two earlier pages, with agreement across the matching evidence. You can accept a suggestion in **Review word…**. Earlier projects can supply vocabulary immediately. Recognizing a page with this version adds the shape samples.

For scans with slight shifts or ink variation, enable **Tools → Training & experiments → Match similar symbol images**. When there is no earlier exact example in the same OCR language, YAGF tries offsets of up to one cell on its 16 × 16 grid. A match requires at least 90% overlap of the combined ink area, with every ink cell within one cell of ink in the other image. Conflicting readings suppress the visual suggestion. The option works locally with shape samples already saved in the project.

After you correct `QWldget` to `QWidget`, selecting another unreviewed `QWldget` anywhere in the same book shows **Review suggestion: QWidget…**. Open the review, choose a reading from **Choose a correction from this book**, compare it with the scan, and click **Use correction**. Cancel discards the choice. Undo and redo update both the word and the suggestions it contributes. Saving and reopening the project restores its correction memory.

Matching is local and case-sensitive. Exact OCR readings take priority. When there is no exact match, alphabetic tokens of 5–80 letters can match a previous OCR reading by one insertion, deletion, or substitution. Digits and punctuation require an exact match. Up to three alternatives show the OCR reading, replacement, match type, and number of examples. Matching words immediately before or after the target on the same line rank alternatives, followed by example count.

**File → Export → OCR data → Verified corrections…** writes one JSON Lines record per eligible word across the book. Each record contains the corrected `text`, `original_text`, a base64-encoded PNG crop in `png_base64`, the page and word IDs, OCR engine, language, confidence, and processed-page pixel box `[x, y, width, height]`. The export uses the same page orientation, PDF resolution, and preprocessing as the editor. It runs locally and can be cancelled.

Both memory and export use reviewed single-token text changes with one source word, one matching source box, and recorded OCR confidence. This excludes unchanged readings, inserted words, and estimated split or merged boxes. The exported pairs can be used for later model training.

### Learn the prose typeface of one book

Use **Tools → Training & experiments → Find math letters in running text…** and select the book’s model. The review looks for an isolated printed letter beside ordinary words, as in “a circle of radius *R*.” Select a row to compare its OCR context with the scan. **Locate on page** centers the scan on that letter. **Include characters with no prose reference** shows additional isolated letters whose OCR readings have no prose templates.

The search uses words on the same OCR line, their spacing and their height. It skips letters inside words, including italic words, and ignores recognizable expressions such as `f(x)` and `x = 0`. In a project it also omits marked formula, picture and table areas when their coordinates match the displayed scan. Fragmented formulas and one-letter prose words can still produce findings. A model with Greek examples can also recognize some letters that general OCR reads as digits or signs. Review leaves the recognized text intact.

The running-text search also handles a letter at the edge of a parenthesized quotation. If the OCR box for a letter overlaps nearby punctuation, the search uses gaps in the printed ink to recover the letter’s bounds. When low-confidence OCR assigns two overlapping letters to one connected shape, the review can offer a single math letter for the whole shape. The row shows both the suggested letter and the original OCR reading.

To train, render several representative pages of the same book at the resolution you will review. Mixed prose and math are fine. With Python 3.9+, Pillow 9.1+ and NumPy available, run the installed command or use `python3 tools/prose_typeface.py` from a checkout.

```sh
yagf2-prose-typeface collect --language rus letters.json.gz scans/page-*.png
yagf2-prose-typeface train letters.json.gz book-typeface.json
yagf2-prose-typeface inspect book-typeface.json held-out-page.png page-review.json
```

Collection uses the selected Tesseract model and its word dictionary. Put `tesseract`, `combine_tessdata` and `dawg2wordlist` on your path, or provide `--wordlist words.txt` with one accepted word form per line to use an independent dictionary. The default selection requires at least five alphabetic characters, a dictionary match, distinct character boxes and word confidence of at least 90. The collector excludes all-capitals and explicitly styled words. Training also estimates slant across whole words and filters examples that differ from the dominant slant. The shape comparison preserves each character’s slant and aspect ratio.

Use at least three distinct pages with eligible words. The trainer reserves every fourth eligible page starting with the third for calibration. A letter needs samples from at least two fitting pages and three different words, at least twelve fitting crops and eight calibration crops. Letters with less evidence stay unmodeled. Reserve additional pages for evaluation. To train on a Jetson, copy the script and the compressed samples there, run the same `train` command, and copy the resulting model back. Training uses the CPU. The samples contain word readings, page names and normalized glyphs. The page scans can stay on the desktop.

The command uses the same prose search by default. Use `inspect --scope page` to reproduce the earlier whole-page experiment. The JSON review uses pixel boxes in left, top, right, bottom order, with exclusive right and bottom edges. A score of 2 means the distance to the closest stored example of the same OCR letter was twice that letter’s threshold. Use the score to rank visual mismatches for review. [Pilot results on a Russian calculus book](benchmarks/prose-typeface.md)

To add examples of Greek letters and italic variables from the same book, supply a saved YAGF project with recognition history. The trainer uses accepted formula transcriptions with their original crops, or formula readings with confidence of at least 90 out of 100 and known crop coordinates. A dedicated single-formula input can supply the whole crop. Some engines omit confidence. For those readings, accept the formula in the inline formula editor or supply a visually checked crop.

~~~sh
yagf2-prose-typeface learn-formulas book-typeface.json book.yagf.json book-with-formulas.json
yagf2-prose-typeface inspect book-with-formulas.json held-out-page.png page-review.json
~~~

For separately saved crops, pass a JSON manifest in place of the project. Each image contains the transcribed expression and its path is relative to the manifest. Mark a reading reviewed after comparing it with the scan.

~~~json
{"format":"yagf-formula-crops/1","formulas":[
  {"image":"alpha-equals-x.png","latex":"\\alpha=x","reviewed":true}
]}
~~~

The trainer aligns simple single-line expressions where each printed symbol occupies a separate group of ink columns. Single-character scripts must also fall on the expected side of the baseline. Numbers and operators can anchor the alignment. The trainer also stores aligned printed digits as comparison examples. A reviewed crop containing a single known Greek letter or digit is valid input. The trainer skips stacked fractions, touching glyphs with ambiguous boundaries, upright text commands and multi-letter names. You can add another batch by using the enriched model as input and choosing a new output file.

Open the enriched model in the typeface review to see **Math letter** suggestions first. Each row shows the suggested letter, the original OCR reading and nearby words. A suggestion requires a close visual match that is distinct from both the other learned formula letters and the book’s prose letters. Letters inside words are skipped before this check. In the JSON report these entries have status `formula_match`, the printed-letter suggestion in `suggested`, and the ink distance in `distance`. Smaller distances mean closer shapes.

For Greek letters, include examples of the missing letter from other pages of the same book and verified digit crops at the review resolution. The prose search considers a standalone OCR digit when the model has at least two distinct examples of that digit. A Greek suggestion must beat the book’s printed digits, prose letters and other formula letters. A standalone `@`, `&`, `%` or `©` reading requires two distinct examples of the proposed Greek letter and a closer shape match. The review continues to skip digits and signs inside words and multi-digit numbers. On the calculus scan this recovered printed ζ read as `6` and α read as `%`.

For italic *z* read as `2`, include at least two distinct examples each of printed *z* and the numeral 2. You can add individually reviewed crops of both using `learn-formulas`. A standalone `2` in running text can then appear as **Math letter z · OCR read 2** when its ink matches *z* more closely than the competing letters and digits. Click the row to compare the suggestion with the scan.

### Teach new OCR symbols

Select a word in the page or word list, highlight a misread symbol in its text, and choose **Tools → Training & experiments → Teach selected symbol…** (also in the text context menu). Enter the intended character, such as `ψ` or `☺`, and choose **This book** or **All projects**. The language field limits the rule to an OCR language or combination, such as `rus`; leave it empty to apply across languages.

Check the highlighted source crop, draw a tighter rectangle if needed, and click **Save crop / add seed**. **Find similar images** searches the selected page range, including pages that have no OCR yet, and collects crops plus their page positions and existing readings. Search includes strong matches and less similar shapes for negative examples. Every search proposal starts as **Needs review**. Select examples and use **Approve match**, **Approve non-match**, or **Review later**. **Refine crop…** loads the example's page so you can adjust its rectangle; a changed crop needs review again. Saved examples from other books retain their images; open the original book to refine their source rectangles.

Approve at least two matching examples and one non-matching lookalike, then click **Train approved examples**. Choose **This computer** or **Jetson / remote host**. The default remote URL is `http://127.0.0.1:8770`, intended for an SSH tunnel to the training worker. Optional service tokens last for the dialog session. Training uses only reviewed masks; pending examples are excluded. Changing approved examples, the target character, or languages requires retraining. A rule holds up to 256 examples; refine the page range or remove redundant crops to gather further variants.

**Preview trained rules on this book…** lists proposed replacements and asks before preparing them. **Save** accepts the rules and those replacements. Book rules, crops, and trained models are stored in the project; applying them to existing pages and editing book rules support Undo/Redo. Save the project to retain them. Shared rules are stored in `~/.local/share/yagf/symbol-rules.json` (or the configured XDG data directory). **Import…** and **Export…** transfer a rule and its reviewed dataset between machines. **Tools → Training & experiments → Symbol recognition rules…** reopens the manager.

Saved, enabled models augment future OCR automatically. The augmentation is a small trained prototype classifier over normalized ink shapes, with an acceptance radius learned from the positive examples and rejection against reviewed negatives. Visual search uses connected shapes and [OpenCV template matching](https://docs.opencv.org/4.x/de/da9/tutorial_template_matching.html). Inference runs locally after base recognition. Existing reviewed text is preserved, competing labels suppress ambiguous matches, and **Use raw OCR output** bypasses augmentation. Embedded characters need an exact alignment between the existing word and Tesseract's character boxes; uncertain alignment keeps the base reading. Completely unread symbols can be inserted beside an existing text line when their reading order is clear. Non-text blocks and formula/figure/table regions are excluded from these insertions. Models should be reviewed against the book's fonts and print quality; the dialog reports training completion, without claiming held-out accuracy.

The optional [Jetson worker and SSH tunnel](../service/SYMBOL_TRAINING.md) use Python's standard library. Remote training sends reviewed 16 × 16 masks and labels; the resulting portable model returns to YAGF for local use. Full page images and authentication passwords are not needed by this training service.

### Native OCR adaptation
**Tools → Training & experiments → OCR training and adaptation…** provides one workflow for reviewed line
images, corrected transcriptions, training/validation partitions and engine-native
model versions. Choose book-specific or reusable models, compare held-out CER,
and explicitly enable a validated candidate; selection is undoable. Tesseract and
Kraken native training run on a configured inference host. PaddleOCR has an
adapter/export workflow but requires a compatible native training environment and
checkpoint before its profile becomes ready. Existing symbol rules continue to
work alongside native models. See [setup, limits and usage](../service/NATIVE_TRAINING.md).

### Discover services and use multiple OCR engines

Open **Tools → Recognition settings…** (also available from
**OCR engine…**). Discovery checks configured URLs and standard OCR ports on hosts
you name. The default `127.0.0.1` includes existing SSH forwards. A specific URL
probes a different port or a service behind a URL prefix. Discovery sends health
checks only.

Select a service and **Use selected as primary**, or keep the current primary.
Check **Use together** for up to three companions and **Save**. The next page,
block or batch recognition starts the engines concurrently. A failed companion
produces a warning and preserves the primary reading.

Choose **Tools → Review → Review OCR readings…**, also in the **Recognize** dropdown, to
compare source crops, primary lines and independent readings. **Use this reading**
updates the selected line/block in the review window; **Save** applies those
choices with Undo/Redo. Larger paragraph/page-only outputs remain inspectable under
**Show complete engine output** when there is no safe line match. Comparison
readings are saved with the project, independently of exported text. Changing
page geometry clears their coordinates; Undo restores them.

An inference gateway can advertise configured text models, reusable validated
models and running vision/formula services through a local SSH forward.
Configure the gateway URL for your own deployment. The service library and companion choices are remembered;
tokens stay in memory. See [setup and limits](../service/OCR_DISCOVERY.md).
